# 0007. Serialization formats: binary documents, JSON, and cvar config

- **Date:** 2026-10-11
- **Status:** Accepted

## Context

CLAUDE.md §8.1 asks core for "a binary writer/reader with versioning, and a
simple text format (JSON subset) for editor and scene files", and for
console variables "editable at runtime from the editor and config files".
§8.7 wants scene files diffable in git and cooked to binary; §8.8 wants
every parser fuzzed and malformed input never to crash. The cooked asset
format (`.nph`, offset-based, memory-mapped) is a Phase 6 design; what is
decided here is the general-purpose layer under it and beside it.

## Decision

1. **Binary documents** are little-endian, fixed-width scalars written by
   `NphBinWriter` and read by `NphBinReader`, a bounds-checked cursor that
   returns `NPH_RESULT_END_OF_STREAM` instead of ever reading past its
   range. Floats are stored as their IEEE-754 bits. Strings are a u32
   length followed by bytes, read back as views into the data.
2. **Versioning is structural, not a number alone.** A document is
   `{magic, version}` followed by `{tag, size, payload}` sections and a
   trailing CRC-32C. The header's version is range-checked
   (`NPH_RESULT_VERSION_MISMATCH`), and unknown tags are skipped by size,
   so an older reader survives a newer writer's additional sections and a
   newer reader can keep reading old sections. Corruption is caught by the
   checksum before any section is trusted.
3. **Text is strict RFC 8259 JSON**, read into a tree owned by one
   `NphJsonDoc` (nodes and strings in chunks, one free) and written in a
   canonical compact or pretty form; a streaming writer emits without a
   tree. No comments, trailing commas, or non-finite numbers: tool-written
   files with one canonical form diff cleanly in git, which §8.7 values
   above hand-editing conveniences. Limits (depth 128, number length 64)
   bound recursion and buffers so hostile input cannot exhaust them.
4. **cvar config is a line format**, `name = value` with `#` comments and
   optional double quotes, not JSON: it is what users and launch scripts
   write by hand, and a line-per-setting file merges and diffs trivially.
   Values for names that are not registered yet are kept pending and
   applied at registration, so a config file can be loaded before every
   module has started.
5. **Every parser has a libFuzzer target** (`tests/fuzz`) with a seed
   corpus, built under Clang with `-fsanitize=fuzzer` on top of the Debug
   configuration's ASan and UBSan, and run nightly. Fuzz targets assert
   round-trip properties (write then parse gives the same text; what the
   cvar writer emits is readable), not just "no crash".

## Alternatives considered

- **A tagged binary format with self-describing fields** (like MessagePack
  or Protocol Buffers): more flexible, but every field pays a tag and the
  reader pays a dispatch; sections give the forward compatibility that
  matters at a fraction of the cost. Self-description belongs to the
  reflection metadata of the ECS (§8.7), not to the byte format.
- **JSON with comments and trailing commas (JSON5/JSONC)**: friendlier to
  hand-edit, but there is no single canonical output, and every external
  tool that touches the files would need the same dialect.
- **JSON for cvar config**: structured and reusable, but a settings file
  edited in a text editor and generated by a launcher is better served by
  one line per setting with comments.
- **A streaming (SAX-style) JSON reader instead of a tree**: lower memory,
  but every consumer would carry its own state machine; the tree is small
  (nodes in 16 KiB chunks) and editor files are not large.

## Consequences

- Scene and editor files are text until the cooker produces binary; both
  paths exist in core now and are exercised by the `core_hello` sample.
- Any change to the binary scalar encoding or the section layout is a
  format version change, recorded in the magic/version of each document
  type.
- The fuzz workflow adds a nightly Clang build with fuzzer instrumentation;
  a reported crash is a release blocker for the parser involved.
